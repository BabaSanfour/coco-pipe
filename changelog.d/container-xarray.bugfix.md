`DataContainer` is now a thin layer over one `xarray.DataArray` (`container.data`, also returned by `to_xarray()`); xarray is a new core dependency. Every coordinate, `y` and `ids` belongs to one dimension, fixed when the container is built, so slicing can no longer attach a coordinate to the wrong axis. A coordinate, `y` or `ids` of the wrong length raises, `isel` raises on an unknown dimension, and a value that fits no dimension is stored in `meta`. `X`, `dims`, `coords`, `y` and `ids` are read-only views: use `container.replace(...)` to change them (`coords` can no longer be edited in place, and `dataclasses.replace` no longer applies). The unused `center`, `zscore`, `rms_scale`, `baseline_correction` and `combine_coords` methods are removed. `concat` and `select` run on xarray: `select` now raises `KeyError` for a key that is not a coordinate, where it used to warn and return everything, and its `fuzzy` option is removed. `flatten`, `stack` and `unstack` also run on xarray; `stack` now expands `y`, `ids` and per-observation coordinates whatever the name of the new dimension. `aggregate`, `with_features`, `obs_table`, `observation_frame` and `feature_schema` read from the array too; `aggregate` keeps the coordinates of the other dimensions (e.g. `feature_family`), which it used to drop.
